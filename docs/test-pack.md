# Personal CPU-first face and voice test pack

The target is the user's Windows machine with an Intel Core i5 10th-generation
U-series CPU and 16 GB RAM. Actual laptop performance has not been measured.

## Deliverable

`artifacts/face-voice-test-pack.zip` contains a standalone `index.html`, an original
rigged GLB, three external stock neural-voice WAV references, and a separate
native-rendered eSpeak timing-baseline video. Extract the archive fully, then
open `index.html`. No Python, external CDN, neural model, or web server is needed
to inspect the model or play the supplied media. Edge/Chrome/Firefox with WebGL 2
can show the manual rig inspector; a native-rendered rest image is the fallback.
The offline browser behavior was tested in Linux Chromium; Windows has not been
executed here. The pack contains **no Windows native engine executable**.

## Asset and audio provenance

- `model/jali-android.glb`: original procedural Jali android, generated by
  `tools/make_character.py`. It has 11,392 vertices, 20,736 triangles, two bones,
  blended skin weights, and three named mouth-position morphs. No purchased or
  scanned human face asset is used. It is a stylized android, not a realistic
  production facial rig. The source generator is included.
- Three mono PCM16 / 44.1 kHz WAVs were generated through Arena's speech tool with
  the selected stock voice. They are external neural audio references, **not a
  local neural implementation or a clone of the user**. Measured durations are
  12.15, 10.23, and 11.19 seconds. Their requested text, signal checks, hashes,
  and explicit absence of alignment are recorded in `manifest.json`.
- `baseline/04-local-phoneme-baseline.mp4` uses a **different**, built-in eSpeak
  voice. Its own actual phoneme events drive the actual native Vulkan renderer.
  `baseline/phonemes.json` and `native-metadata.json` retain that evidence.
- The standalone inspector is WebGL, not Vulkan. It morphs then skins the same
  GLB with manual sliders and the engine's jaw-rotation convention. It does not
  animate to the external neural recordings.
- No third-party runtime or model redistributable license is granted by these
  outputs. The repository still needs an owner-selected distribution license.
  The exact external reference voice's downloadable model/runtime is not supplied.

## Rebuild and verify

First bootstrap the native Linux development runtime as in the README. Place the
three already-generated WAVs in `artifacts/face-voice-test-pack/audio/` with the
filenames listed in `tools/build_test_pack.py`. The pack builder validates the
WAVs; it does **not** regenerate the external neural voice or download a model.

```sh
.venv/bin/python tools/build_test_pack.py --software-vulkan
.venv/bin/python -m http.server 8080 --bind 0.0.0.0 \
  --directory artifacts/face-voice-test-pack
# In another terminal:
node tools/smoke_test_pack.cjs
.venv/bin/python tools/build_test_pack.py --seal-only
```

The browser check tests both HTTP and direct `file://` loading, four visibly
changing rig poses, PCM playback for all three references, baseline-video
playback, mobile overflow, no external network dependency, and no page errors.
The screenshots/report live in `proof/`. `--seal-only` updates checksums and the
ZIP after those reports have been added. The WAV/inventory unit tests need only
standard Python and run in the normal CPU CTest group.

## What remains for the neural milestone

A permitted locally runnable neural provider must still be installed and tested
on CPU. Its **actual generated audio** needs genuine phoneme alignment before it
can drive the face. Do not reuse the baseline video's eSpeak cues or label a
manual/energy-driven animation as neural alignment. A hardware GPU is not
required to start correctness testing, but throughput/latency cannot be promised
without measurements. WSL2 may be a Windows development option for the existing
Linux transport; it has not been validated on the user's laptop.
